## Format observations (.mdzip)

The file is a plain ZIP (deflate) whose entries carry no extension. Entry roles:

- `PROJECT-<uuid>`: zero-byte marker holding the project ID.
- `Records.properties`: Java properties file. Its first line is `#Compatibility entry`, then a timestamp, then entry=entry mappings.
- `Binaries.properties` / `personal-Binaries.properties`: map `com.nomagic.magicdraw.uml_model.model=BINARY-…,BINARY-…`. This is the list of binary streams owned by each model resource.
- `com.nomagic.ci.metamodel.project`: root `project:Project` (ns `http://www.nomagic.com/ns/cameo/client/project/1.0`, EMF XMI 2.0). It holds `ownedSections` (model, commonprojectoptions, personalprojectoptions, commoncodeengineering…) and `projectUsages` for used projects or profiles, with `usedProjectURI` (often a file path that shows the install directory, e.g. `CameoSystemsModeler/2021xR2_HF2`) and `<properties key="usedVersion" value="2024x Refresh2"/>`. A `key="fileVersion"` is also present (value 3 in 2026x).
- `com.nomagic.magicdraw.uml_model.model`: **the main model**. Root `xmi:XMI` with `xmlns:uml='http://www.omg.org/spec/UML/20131001'`, `xmlns:xmi='http://www.omg.org/spec/XMI/20131001'`, and SysML `http://www.omg.org/spec/SysML/20181001/SysML` (SysML 1.6 in 2021x and later; `20150709` = SysML 1.4 in 18.x/19.0). Profile namespaces follow the pattern `http://www.magicdraw.com/schemas/<Profile>.xmi`. It contains `<xmi:Documentation><xmi:exporter>MagicDraw UML</xmi:exporter><xmi:exporterVersion>2021x</xmi:exporterVersion>` and `<xmi:Extension extender='MagicDraw UML 2021x'>` with `plugin pluginName/pluginVersion` and `req_resource` elements, then `uml:Model`. Stereotype applications are top-level elements after the model, e.g. `<sysml:Requirement base_Class=… Text=… Id=…/>` and `<MagicDraw_Profile:DiagramInfo …>`. Element IDs embed the version, e.g. `_2021x_2_6f4019b_…` or `_19_0_3_…`.
- `com.nomagic.magicdraw.uml_model.shared_model` (plus `com.nomagic.magicdraw.uml_model____sharepoints.shared_model`, root `uml:Package`): present in library or profile projects that share packages. In those projects **most of the content lives here**, and `.model` is nearly empty (NIST, OpenSUT_MPS, SAF_Profile).
- `proxy.local__PROJECT$h<id>_resource_com$dnomagic$dmagicdraw$duml_umodel$dshared_umodel$dsnapshot`: cached snapshots of used projects such as UML_Standard_Profile and SysML. Name escaping: `$d`=`.`, `$h`=`-`, `_u`=`_`. These use a **different serialization**: EMF-native `uml:Package` or `xmi:XMI` with `xmlns:uml="http://www.nomagic.com/magicdraw/UML/2.5.1.1"` (`2.5.1` in 19.0, `2.5` in 18.x), `xsi:type` and `ID` attributes. The matching `…metamodel$dproject$dsnapshot` entries are `project:Project`.
- `com.nomagic.ci.proxy.snapshot.descriptor.descriptors`: root `snapshot:SnapshotInfoContainer` (ns `http://www.nomagic.com/ns/cameo/client/snapshot/1.0`). `com.nomagic.ci.persistence.local.proxy.privatedependencylist`: root `snapshot:PrivateDependenciesContainer`.
- Options: `…commonprojectoptions` has root `project.options:CommonProjectOptions`. `personal-…personalprojectoptions` has root `project.options:UserProjectOptions`. `com.nomagic.magicdraw.ce.*codeengineering` entries are `xmi:XMI`.
- **Diagrams**: each diagram is a `uml:Diagram` under `xmi:Extension/modelExtension/ownedDiagram` in the model XMI. It contains `xmi:Extension/diagramRepresentation/diagram:DiagramRepresentationObject` (`xmlns:diagram='http://www.nomagic.com/ns/magicdraw/core/diagram/1.0'`, `xmlns:binary='http://www.nomagic.com/ns/cameo/client/binary/1.0'`), with attributes `type='SysML Block Definition Diagram'` and `umlType='Class Diagram'`. It can also carry `diagramProperties`, which is a **hex-encoded XML** string (`PropertyVisitorAcceptor`). Its child `diagramContents` (with `contentHash` and `exporterVersion`) contains `<binaryObject xsi:type='binary:StreamIdentityBinaryObject' streamContentID='BINARY-<uuid>'/>` and `usedObjects href` elements.
  - The `BINARY-<uuid>` entry is **uncompressed plain XML** (stored deflated in the ZIP) with root **`<mdOwnedViews>`**. Its children are `mdElement elementClass='Class|DiagramFrame|…'`, each with `elementID xmi:idref`, `geometry` "x, y, w, h", nested `mdOwnedViews`, and `symbolStyleID`. An empty diagram is a 55-byte `<mdOwnedViews/>`.
  - Other BINARY entries are raw attachments: PNG (image shapes and icons in SAF_FFDS), JPEG (TMT) and PDF (SAF_FFDS). Detect them by magic bytes.
  - **Tables and matrices** (Generic Table, Instance Table, Requirement Table) have a `binaryObject` with no `streamContentID`. Their configuration is a stereotype application in the model, e.g. `<MagicDraw_Profile:DiagramTable base_Diagram=… displayMode='List'>` with `columnIds` values such as `QPROP:Element:name` and `hideColumns`. Rows come from scope, element types or queries, so they are not materialized.

## .mdzipx

Documented by No Magic under "CATIA Systems Synthesis": "An integrated MDZipX plugin helps to improve the display of diagrams on the 3DEXPERIENCE platform by converting them to the MDZipX file". "The .mdzipx file contains: the .mdzip file [and] the .svg file for each diagram [and optionally] data from used projects". It can be generated locally or published to Teamwork Cloud.
Sources: https://docs.nomagic.com/spaces/MD2024x/pages/136709707/CATIA+Systems+Synthesis and https://docs.nomagic.com/plugins/viewsource/viewpagesrc.action?pageId=95734145
**Not verified**: no sample was found, and the internal entry names and layout (presumably ZIP) are unconfirmed.

## .rdzip

This is a "resource distribution file" for the Resource/Plugin Manager: a plugin or resource bundle (e.g. `core.rdzip`) that "can contain plugins/profiles/model libraries etc.", with each resource "packed to separate .zip files". Each resource zip follows the install-directory layout (`profiles/*.mdzip`, `templates/<name>/<name>.mdzip`, `samples/…`, plugins as a jar plus a plugin descriptor xml) plus a descriptor `data/resourcemanager/MDR_<Type>_<Name>_<id>_descriptor.xml` (root `resourceDescriptor`, with `<installation><file from= to=/>`). The bundle is built with `com.nomagic.magicdraw.resourcemanager.distribution.GenerateResourceDistributionFileTask <resourceDir> <outputDir> <name>`.
So an .rdzip is **a ZIP of resource ZIPs, which in turn contain .mdzip files**. That this is a ZIP-of-ZIPs is inferred from the docs and not verified on a real .rdzip. The SAF release zips in `resource_bundles/` show the inner resource-zip layout for real.
Sources: https://docs.nomagic.com/display/MD2021x/Building+a+resource+distribution+file ; https://docs.nomagic.com/spaces/MD2024x/pages/136715095/Creating+required+files+and+folders+structure ; https://docs.nomagic.com/spaces/CC4TWC2022x/pages/90400062/Installing+Cameo+Collaborator+Publisher+plugin ; https://docs.nomagic.com/display/MD2024x/MagicDraw+file+format (official .mdzip entry list)
