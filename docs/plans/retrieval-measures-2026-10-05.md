# Plan: retrieval's untested measures, 2026-10-05

- **Status:** In progress, started on 2026-10-05 ("Please proceed with retrieval's untested
  measures"). CP1 to CP3 measured; stopped for the maintainer on generated chunks (RM-04).
- **Step prefix:** `RM`, so steps are `RM-01`, `RM-02` and so on.
- **Addresses:** the roadmap's first item, left open by plan RE
  (`docs/archive/plans/retrieval-evaluation-2026-09-30.md`):
  - **RE-08:** generated and ledger chunks, in or out;
  - **RE-05:** windows over the pages.

## Why

**Ledger and generated chunks** are 12,871 of the 83,804 chunks in the 0.19.0 tree
(`out/v019/on`): 6,417 ledger and 6,454 generated by the LLM. Nothing has measured whether they
help retrieval or only crowd it.
- **What they are for:**
  - **ledgers:** lists ("Which requirements cover thermal control?", "List the activity
    diagrams");
  - **generated chunks:** extra recall, especially for questions in other words than the
    model's.
- **What the README says:** "weight or filter them separately". But the maintainer's stack reads
  files (plan RE, decision 14), so it can't filter by kind: what `rag/` holds is what it searches.
- **A default, then (ADR-0027):** keep them in `rag/` or not, by measurement.

**Windows over the pages:** plan RE meant to measure the stack reading the Markdown pages. Since
then `rag/` was made for it, and the README says to point the stack at `rag/text/` alone. The
question now is what it costs if the stack is pointed at the pages, or at the whole tree.

## Method

- **The tree:** `out/v019/on`, the samples and the fiction at 0.19.0 with the LLM. The current
  code writes the same per-project output.
- **The reference:** its release-check run, `out/v019/retrieval-on`. It covers the 226 standing
  questions (`questions-ra-th-is.jsonl`), over `rag/`, with:
  - e5-large without prefixes, BM25, and their fusion;
  - each of them reranked by Qwen3's 0.6B reranker.
- **Leaving kinds out** happens in the harness, with no rebuild: the same files, less some. The
  embeddings are cached by text, so a variant costs only the reranking of new candidates.
- **The comparison:** `scripts/compare_retrieval.py`, paired by question.
- **What the questions can't show:**
  - The fiction's questions ask for facts and parts, and a generated summary helps them only
    where it restates a fact.
  - Questions that only a summary answers ("what does this part of the activity do?") can't be
    graded by construction.
  - So the measure says what generated chunks do for fact questions, not all they are for.

## When to stop and ask

- **A trade-off:** a kind whose removal helps one question set significantly and hurts another
  stops for the maintainer with the numbers, as IS-05 did.
- **A change to what `rag/` holds:** a net gain with no set losing is taken (ADR-0027). It is
  still reported before it ships, since users see what `rag/` holds.
- **Cost:** if the pages' embedding grows past about three hours, or windowing them exceeds the
  memory cap, the plan stops.
