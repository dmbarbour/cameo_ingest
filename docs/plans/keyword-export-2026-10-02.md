# Plan: searching the corpus without tools, 2026-10-02

- **Status:** Proposed on 2026-10-02.
- **Step prefix:** `KX`, so steps are `KX-01`, `KX-02` and so on
- **Addresses:** the tentative plan "Keyword search over the corpus, and an export to search
  without tools" (plan index). The maintainer's constraints, 2026-10-02:
  - the corpus is shared through SharePoint and read with common office tools;
  - neither Python nor a database can run where it is read;
  - their RAG service takes uploads, but can't do keyword search.

  They lean towards one large Excel file that tracks files, summaries and requirements. A
  static page (in the manner of TiddlyWiki) or Obsidian are the alternatives.
- **Research:** `docs/research/keyword-export-2026-10-02.md` (KX-01). It finds:
  - SharePoint Online downloads HTML files rather than showing them;
  - Excel for the web opens workbooks up to 100 MB, but follows only absolute links;
  - `HYPERLINK()` formulas take up to 255 characters, while hyperlink objects are limited to
    65,530 per sheet;
  - SharePoint search indexes `.txt` files but not `.md`.
- **Related:** plan RE, whose baseline found that keyword search finds requirements by id
  where embeddings don't. Plan RF's index across models (`CROSSREF.md`, `index/ids.jsonl`)
  becomes one of the workbook's sheets.

## Decisions

Proposed, with a recommendation each; the maintainer decides.

| # | Question | Recommendation |
|---|---|---|
| 1 | The format | **A workbook first** (`CATALOG.xlsx` at the tree's root). A single-file HTML search page only if the workbook falls short (KX-08, deferred), since SharePoint would make people download it. Obsidian and VS Code get a README paragraph: they open the tree's pages as they are. |
| 2 | How links reach SharePoint | **A base URL**: the address of the SharePoint folder that the tree is uploaded into, as a tree setting (`--catalog-url`). Without it, links are relative, and work in desktop Excel with the tree downloaded or synced. |
| 3 | What a row links to | **The chunk's `rag/text` file**: short, exactly the item's text, previewed and indexed by SharePoint, and short enough for `HYPERLINK()`. A `Pages` sheet links every page as well. This assumes `rag/` is uploaded with the tree; if not, rows link to their pages, and only the `Pages` sheet has hyperlinks. |
| 4 | Which elements | **Every element with a name or documentation**, plus every requirement, diagram and package. Unnamed structural items (literals, instance values, unnamed pins and the like) are left out, and the `About` sheet counts them. |
| 5 | Generated text | **Included and marked**: package summaries and diagram descriptions, each saying which model wrote it ("generated by …; not part of the source model"). |
| 6 | On by default | **Yes**: a tree-wide switch, `--catalog/--no-catalog`, applied on every run (the maintainer's rule for switches). It adds one dependency, XlsxWriter (pure Python, BSD licence). |

## The workbook

Each sheet has a frozen header row and an AutoFilter, so that a column's filter ("Text Filters
› Contains") also searches. Text is written as text, never as a formula or number, so that an
id like `1.2.3` or a text starting with `=` stays as written. Long text is cut, with "…", and
the link leads to the rest.

| Sheet | One row per | Columns |
|---|---|---|
| `About` | | What the workbook is; how to search (desktop: Ctrl+F, Options, Within: Workbook; on the web: the `Search` sheet, or a column's filter); what "generated" means; the tool's version; rows and items left out per sheet |
| `Search` | requirement, element in scope, diagram, package, summary | Type, Id, Name, Project, Where (qualified name), Text, Link. The sheet for Ctrl+F: everything is findable from it, wherever Find's scope ends. |
| `Requirements` | requirement | Id, Database number, Name, Text, Project, Package, Satisfied by, Verified by, Derived from, Derived by, Refined by, Other relationships, Diagrams, Link |
| `Identifiers` | identifier and element (the index across models) | Id, Project, Element, Kind, How (its id, in its text, satisfies it…), Snippet, Link |
| `Elements` | element in scope | Kind, Name, Qualified name, Project, Stereotypes, Documentation, Link |
| `Relationships` | relationship | Source, Relationship (as worded on the pages), Target, Stereotype, Project |
| `Diagrams` | diagram | Name, Type, Owner, Project, Shapes, Description (generated), Link |
| `Summaries` | generated summary | Of (package, part, module), Project, Summary, Model, Link |
| `Projects` | project | Project (file name), Label (`TMT [9ffd7a2c]`), Content sha256, Input paths, Saved by, counts, README link. These are the source files that the maintainer's tracing ends at. |
| `Pages` | page | Path, Project, What it holds, a hyperlink (5,461 pages: within the 65,530 limit) |

## Steps

| Step | What | Status |
|---|---|---|
| KX-01 | **Research** (`docs/research/keyword-export-2026-10-02.md`). | Done |
| KX-02 | **Catalog records per project.** A module `catalog.py`, with `project_catalog(view, sink)`, writes `index/catalog.jsonl` at build time, from the in-memory model. It uses the vocabulary of `semantics`: labels, kind words, requirement ids and relationship wording, as on the pages. There is one record per row of the per-project sheets. Each record names its main chunk's id and its page (project-relative). `TableWriter.write_indices` writes the file; it is the workbook's only input from a project (AR-012: no reading of CSV tables or rendered text). | |
| KX-03 | **The workbook writer.** A module `workbook.py`, with `write_catalog(path, rows, links)`, built on XlsxWriter in constant-memory mode (row by row, so that memory stays flat whatever the corpus).<br>**Text:** strings only, with `strings_to_formulas`, `strings_to_numbers` and `strings_to_urls` off. Cells are cut at limits named in one place.<br>**Links:** `HYPERLINK()` formulas to chunk files, when the URL fits 255 characters; otherwise the path as text. Hyperlink objects on `Pages`.<br>**Reproducibility:** fixed document properties (no creation time), so that the same tree gives the same bytes (BASE-015). | |
| KX-04 | **The tree step and its settings.**<br>**The step:** `exports.write_catalog(tree)`, in `rebuild` after `write_rag`. It reads each project's `index/catalog.jsonl`, the chunk-to-file map from `rag/meta` (or pages, when `rag/` is off) and the projects' input paths from the state.<br>**Settings:** `TreeSettings.catalog` (on) and `catalog_url`, with the flags `--catalog/--no-catalog` and `--catalog-url URL` (`flag_pair`). Spaces and other characters in the URL are percent-encoded. `--no-catalog` removes the file.<br>**README:** a section, "Searching without tools": the workbook, SharePoint's own search over `rag/text`, and Obsidian or VS Code for those who have them. | |
| KX-05 | **Measure on the samples.** A tree of the samples and the fiction, built under the memory cap. Record:<br>- the workbook's size (to stay under 100 MB, and preferably under 50, the OneDrive limit);<br>- rows per sheet, and items left out;<br>- the build's time and memory;<br>- the same bytes from two builds.<br>Adjust the cut lengths and the elements in scope if the size calls for it. | |
| KX-06 | **The maintainer's check on SharePoint**, with the fiction alone first (small). Upload the tree, with `rag/` and `--catalog-url` set to the folder. Then check, and adjust from what they find:<br>(a) the workbook opens in the browser;<br>(b) the scope of Ctrl+F in Excel for the web;<br>(c) a row's link opens its chunk file, and `Pages` opens a page;<br>(d) SharePoint's search box finds `"RWT-REG-001"` in the chunk files. | |
| KX-07 | **Index pages as `.txt`** (only if KX-06 (d) shows that pages, not chunk files, should be found by SharePoint's search, which skips `.md`). | Conditional |
| KX-08 | **A single-file HTML search page** (only if the workbook falls short). The page, its data and a small search library (MiniSearch, MIT licence) go inline in one file, so that it works when downloaded and opened from disk. | Deferred |

**Checks for CP1:**
- **Tests on the fiction tree** (the session fixture). The workbook is a zip of XML, so the
  tests read it with `zipfile`, with no new test dependency:
  - every sheet is present, with its row count;
  - a known requirement row holds its id, text, satisfiers and link;
  - a text that starts with `=` is stored as a string, not a formula;
  - with `--catalog-url`, a link is the base URL plus the percent-encoded path;
  - two builds give the same bytes;
  - `--no-catalog` removes the file.
- **The rest of the tree:** everything but the new files is unchanged against `out/ra/final-llm`'s
  code (`treediff`, `--no-llm`).
- **Cost:** every project is made again once (a new tool version and a new per-project file),
  with no LLM cost: the answers are in the store.

## When to stop and ask

- The workbook exceeds 100 MB on the samples even with cut text: the maintainer chooses between
  fewer elements, a workbook per project, or desktop-only use.
- Either SharePoint check (KX-06) fails in a way that changes the design: links that SharePoint
  won't follow, or a search scope that makes the `Search` sheet pointless.
