## Subject

This is the first full review of the project: every module in `src/cameo_ingest/` (13
modules, about 2,400 lines), `tests/test_pipeline.py`, `scripts/fetch_samples.py`,
`README.md` and `samples/SOURCES.md`. The review covers correctness, robustness, and the
match between what the README promises and what the tool produces. Performance tuning,
retrieval-quality evaluation, and security beyond archive and XML handling are out of
scope.

## Methodology

1. Read all of the source, the tests and the docs listed above.
2. Ran `uv run pytest`: 18 passed in 7.7 s. Ran `ruff check` with the project
   configuration: clean. A wider rule set (`E,F,W,B,UP,SIM,RUF,PL`) found only style issues.
3. Tested suspected bugs against the public sample models (`scripts/fetch_samples.py`):
   - Listed each sample's declared namespaces and counted its stereotype applications
     with `unzip -p … | grep`.
   - Ran full ingests of `Package_Delivery_Drone`, `SAF_FFDS` and `TMT` with `--no-llm
     --no-render`. TMT took 16.9 s and peaked at 400 MB RSS.
   - Ran `SAF_FFDS` with `LLM._complete` replaced by a stub that returns fixed text, so
     the LLM output path runs without any network call.
   - Built a synthetic `.rdzip` holding one valid project and one truncated project.

4. Investigated the maintainer's findings (BASE-015 to BASE-022):
   - Ran Package_Delivery_Drone twice on the same input, and once on the same bytes copied to
     another directory. Compared the outputs with `diff -r` and chunk by chunk.
   - Hashed every `.mdzip` inside the SAF release bundles and compared them with the
     standalone samples.
   - Checked the first 512 bytes of every `BINARY-*` stream in the samples. This is how the
     BASE-013 correction was found.
   - Counted the LLM calls a full TMT run needs, using the pipeline's own functions.
   - Sent two requests to the maintainer's endpoint through the tool's `LLM` class, with
     the configuration taken from `.env` and the key never printed. This measured latency
     and confirmed that the request format works.
   - Ran two synthetic inputs that share a file name, from different directories, into one
     output directory.

Each finding is marked either **Reproduced** (confirmed by running something) or **By
inspection** (found by reading the code only).

## Decisions

All of these were made on 2026-09-29.

- **BASE-008R1:** Remove `--force`. A run continues into an existing output directory,
  including one left partly written. A non-empty directory that doesn't hold the tool's
  state is refused.
- **BASE-009R2:** Use option (a), `<a id>` anchors. The maintainer had no preference and
  asked for the more convenient and flexible option, which can be changed later.
- **BASE-010R1:** Resolved by BASE-015: run identity comes out of the per-file outputs.
- **BASE-011R1:** Allow 10 GB decompressed per input in total and a 1000:1 ratio. The limits
  should assume valid input.
- **BASE-020R3:** Add `--env PATH`, and use `OPENAI_MODEL` as the last fallback for the model.
  Variables already set in the environment take precedence over the file.
- **BASE-022R5:** Added at the maintainer's suggestion: a replayable fixture database of LLM
  responses. The JSON cache is replaced by this SQLite store as part of this review, ahead
  of the resumable-ingest plan, which also delivers BASE-005R1 and BASE-005R2.

## Findings

### BASE-001: Profile namespaces under `omg.org/spec/UML/…` are read as UML, so stereotype applications become elements

**Severity:** High · **Verified:** Reproduced · **Where:** `src/cameo_ingest/xmi.py:35-38`, `:103`

**Status:** Fixed on 2026-09-29.

`_prefix_for` gives the prefix `uml` to any namespace URI that *contains*
`omg.org/spec/UML/<digits>`, and to any URI that *starts with*
`http://schema.omg.org/spec/UML`. Cameo declares several of its own profiles under that
path:

- `MagicDraw_Profile`: `http://www.omg.org/spec/UML/20131001/MagicDrawProfile`
- `StandardProfile`: `http://www.omg.org/spec/UML/20131001/StandardProfile`
- `Validation_Profile` (SAF_FFDS): `http://www.omg.org/spec/UML/20131001/ValidationProfile`

The stereotype check at `xmi.py:103` requires `prefix not in ("uml", "xmi")`. Stereotype
applications from these profiles fail it and are recorded as top-level elements, and
their `base_*` attributes turn into references.

**Consequences:**
- **Table and matrix configuration is lost.** Cameo stores it in `MagicDraw_Profile:DiagramTable`.
  The README says this configuration is emitted, but for these tables it isn't.
- **Fake element kinds appear.** `DiagramInfo`, `DiagramTable` and similar show up as
  element kinds in the README, `elements.csv` and `elements.jsonl`.
- **StandardProfile «Trace» and «Refine» lose their names.** Relationships using them are
  labelled with the bare metaclass `Abstraction`, so the ledger's `trace` and `refine`
  wording (`ledger.py:35-36`) never applies.

**Evidence:**
- **Package_Delivery_Drone** has about 15 `MagicDraw_Profile` applications. Its README lists
  `DiagramInfo: 11` and `DiagramTable: 1` among the element kinds. Its page
  `diagrams/Requirements_Domain_Table.md` has no table configuration section.
- **Other samples:** SAF_FFDS has about 474 `MagicDraw_Profile` applications and MDK_DocGen
  about 364. TMT has 16 `StandardProfile` applications (all «Create») and MDK_DocGen 83.
- **What isn't shown:** no sample uses «Trace» or «Refine» from StandardProfile, so the
  effect on relationship names was not observed directly.

**Remediation:**
- **BASE-001R1 (done):** Normalize only the bare UML and XMI namespace URIs: a version segment with
  nothing after it, on `www.omg.org` or `schema.omg.org`. Every other URI keeps its declared
  prefix.
- **BASE-001R2 (done):** Add both namespaces to the synthetic fixture, along with a
  `MagicDraw_Profile:DiagramTable` application on the diagram and a `StandardProfile:Refine`
  application on an `Abstraction`. Assert that the table configuration appears on the
  diagram page, the relationship kind is `Refine`, and the ledger shows `refined by`.
- **BASE-001R3 (done):** Assert that Package_Delivery_Drone has no `DiagramInfo` or `DiagramTable`
  element kinds, and that its Requirement Table page shows a configuration section. The
  general version of this check is covered by BASE-007R1. As built, the invariant that no
  element has a `base_*` attribute covers the element kinds on every sample. The pinned
  counts (BASE-007R2) include the drone sample's two diagrams with table configuration.
- **BASE-001R4 (added while fixing; done):** Resolve stereotype tags that hold several ids
  in one attribute, the way `finalize` already does for element attributes. A table's
  scope (`additionalElements`) now lists element names instead of raw ids.
- **BASE-001R5 (added while fixing; done):** Once they were read correctly, `DiagramInfo`
  applications (author, creation and modification dates) appeared on almost every diagram.
  They are now shown as diagram metadata rather than as table configuration. Other
  stereotypes on a diagram are headed "Table / matrix configuration" only when the
  diagram is a table or matrix, and "Stereotypes and tagged values" otherwise.

### BASE-002: All embedded-image chunks in a project share one chunk ID

**Severity:** High · **Verified:** Reproduced · **Where:** `src/cameo_ingest/pipeline.py:166`, `src/cameo_ingest/emit.py:163`

**Status:** Fixed on 2026-09-29.

The chunk ID is a hash of source, container, kind, element-or-file, and salt. Image
chunks are written with `el=None`, `file="images.md"` and no salt, so every image
description in a project gets the same ID. A vector store that upserts by ID keeps only
the last one. The bug only shows when a vision model is configured; without one, no image
chunks are written.

**Evidence:** SAF_FFDS with the stubbed vision model produced 986 chunks but only 969
unique IDs. One ID (`5c3eb6bcc17e2d97a37d5087`) was shared by all 18 `image` chunks.

**Remediation:**
- **BASE-002R1 (done):** Pass `salt=entry` (the archive entry name) when writing each image chunk.
- **BASE-002R2 (done):** In the LLM test, add a second embedded image to the fixture and assert that
  every chunk ID in `chunks.jsonl` is unique. The same assertion across samples is covered by
  BASE-007R1.

### BASE-003: Truncated anchors collide, so links point at the wrong element

**Severity:** Medium · **Verified:** Reproduced · **Where:** `src/cameo_ingest/emit.py:143-144`

**Status:** Fixed on 2026-09-29.

`anchor()` builds `slug(f"{name}-{id}", 120)`, which cuts the string after the id has been
appended. When a name is long, the id is partly or fully dropped. Elements whose long names
share a 120-character prefix then get the same anchor. Links, the ledger rows, and the
chunks' `metadata.file` values (`packages/…md#anchor`) then all resolve to the first match.

**Evidence:** In a fresh TMT ingest, 4,201 of 16,212 anchors are cut at the cap, and 120
anchors are duplicated within the same package file. An example is
`gravity_calibration_duration_scenario.aps_mission_logical.aps_operational_blackbox.peas.calibrationelevationangles.entri`.

**Remediation:**
- **BASE-003R1 (done):** Cut the name part alone, then always append the full slugged id.
- **BASE-003R2 (done):** Add a fixture test with two elements in one package whose names share a
  prefix longer than the cap. Assert that their anchors differ and that each link resolves
  to its own section. The same check across samples is covered by BASE-007R1.

### BASE-004: One unreadable project aborts the whole run and writes no manifest

**Severity:** Medium · **Verified:** Reproduced · **Where:** `src/cameo_ingest/pipeline.py:52-58`, `src/cameo_ingest/cli.py:116-128`, `src/cameo_ingest/archive.py:141-156`

**Status:** Fixed on 2026-09-29.

Errors from `parse_project` and `ingest_project` are not caught per project. In a bundle,
one malformed project stops everything, and the run exits before writing `manifest.json`,
`chunks.jsonl` or the root `LEDGER.md`. Output directories already written are left
without a manifest. The pyproject comment says a bad stream never aborts an ingest, but
that only holds for layout streams (`pipeline.py:78`). `discover` also catches only
`UnsupportedInput` when reading nested members. A CRC or decompression error in a nested
ZIP (`zipfile.BadZipFile`, `zlib.error`) also ends the run.

**Evidence:** I built a `bundle.rdzip` with `good.mdzip` (the test fixture) and `bad.mdzip`,
whose model entry is truncated XML. The run died with `lxml.etree.XMLSyntaxError`,
leaving `good.mdzip/` without `manifest.json`, `chunks.jsonl` or `LEDGER.md`.

**Remediation:**
- **BASE-004R1 (done):** In `cli.main`, wrap each project's ingest in a `try` block. Log the failure
  and add `{"dir", "container", "error"}` to a new `manifest["failed"]` list.
- **BASE-004R2 (done):** Always write `manifest.json`, `chunks.jsonl` and the root ledger for the
  projects that succeeded. Exit with a distinct non-zero code (e.g. 4) when any project
  failed.
- **BASE-004R3 (done):** In `discover`, catch `zipfile.BadZipFile` and `zlib.error` from nested
  members, log them, and skip the member.
- **BASE-004R4 (done):** Test with the good-plus-truncated bundle. Assert the exit code, that
  `good` is ingested, and that `manifest["failed"]` names `bad.mdzip`.

### BASE-005: A corrupt LLM cache entry aborts the run; cache writes are not atomic

**Severity:** Medium · **Verified:** By inspection · **Where:** `src/cameo_ingest/llm.py:77-80`, `:92-93`

**Status:** Fixed on 2026-09-29.

The cache is read with `json.loads(cpath.read_text())` outside the `try` block. A
truncated or empty cache file raises `JSONDecodeError`, and that ends the whole ingest.
This contradicts the README's statement that LLM failures never fail the ingest. A cache
file can be left half-written by a killed run, a full disk, or two runs sharing one
`--cache-dir`, because `write_text` does not write atomically. Separately, the cache key
covers only the model name and the prompt, not the endpoint. Pointing `OPENAI_BASE_URL`
at a different server that uses the same model name returns the old server's answers.

**Remediation:** BASE-005R1 and BASE-005R2 will be delivered by the SQLite LLM store of
BASE-022R5, as decided on 2026-09-29. They stay listed here as requirements that store
must meet.
- **BASE-005R1 (done):** Treat an unreadable cache entry as a miss: log it and call the model again.
- **BASE-005R2 (done):** Write cache entries to a temporary file in the same directory, then
  `replace` it into place.
- **BASE-005R3 (done):** Add `base_url` to the cache key.
- **BASE-005R4 (done):** Test that a corrupt cache file leads to one new call and a valid cache entry.
  As built, the JSON cache is replaced by the SQLite store of BASE-022R5 (`llm.sqlite`).
  An unreadable store file is renamed to `llm.sqlite.corrupt-<time>` and a new one is
  started. A failed lookup counts as a miss. Each response is committed as its own
  transaction, and the key includes the endpoint.

### BASE-006: An unreachable LLM endpoint can stall a run for hours

**Severity:** Medium · **Verified:** By inspection · **Where:** `src/cameo_ingest/llm.py:69-91`

**Status:** Fixed on 2026-09-29.

Each call can take up to three attempts (`max_retries=2`) of up to 120 s each, and a
failed call still uses one unit of the 500-call budget. When the endpoint is down, that
can add up to 500 × 360 s, about 50 hours, before the budget runs out. Every one of those
calls fails.

**Remediation:**
- **BASE-006R1 (done):** After a small number of consecutive failures (e.g. 3), turn LLM enrichment
  off for the rest of the run, log one warning, and record `llm_disabled_after_failures` in
  the manifest.
- **BASE-006R2 (done):** Test with a stub that raises: after the threshold, no more calls are made.
  As built, the threshold is 3 consecutive failures. `run.json` records
  `disabled_after_failures`, and every item skipped afterwards is listed as
  `skipped_disabled`.

### BASE-007: Sample tests check only the exit code

**Severity:** Medium · **Verified:** By inspection · **Where:** `tests/test_pipeline.py:135-142`

**Status:** Fixed on 2026-09-29.

`test_public_samples` asserts only that the run exits 0 and writes `manifest.json`.
BASE-001, BASE-002 and BASE-003 all pass the current suite. The synthetic fixture has no
Cameo profile namespaces, and nothing tests the LLM cache.

**Remediation:**
- **BASE-007R1 (done):** Add checks that every sample run must pass:
  - every chunk ID is unique;
  - anchors are unique within each Markdown file;
  - no element has an attribute or reference named `base_*` (such an element is a
    stereotype application that was parsed as an element).
- **BASE-007R2 (done):** Once BASE-001 to BASE-003 are fixed, pin a few counts for small samples:
  requirements, diagrams, and diagrams with table configuration, starting with
  Package_Delivery_Drone. As built, the pinned counts are elements, diagrams, stereotype
  applications, relationships, requirements, diagrams with table configuration, and
  diagrams with shapes. They cover Package_Delivery_Drone in the regular suite and TMT in
  the slow run.
- **BASE-007R3 (done):** Add an opt-in pytest marker that runs the BASE-007R1 checks on every sample,
  including TMT and SAF_FFDS. That takes minutes rather than seconds, which is why it
  should be opt-in.

### BASE-008: `--force` leaves stale files from earlier runs

**Severity:** Low · **Verified:** By inspection · **Where:** `src/cameo_ingest/cli.py:90-93`

`--force` writes over the existing directory without clearing it. Files from an earlier
run that are no longer produced, such as the page for a renamed package or diagram, stay
on disk. They are not in the new manifest, but any loader that globs `**/*.md` or
`**/chunks.jsonl` will still read them. BASE-016 shows the same problem when two different
inputs share a file name.

**Remediation (decided 2026-09-29):**
- **BASE-008R1:** Remove `--force`. The output directory becomes a workspace that each run
  either starts or continues:
  - **A missing or empty directory** starts a new output.
  - **A directory that holds this tool's state** is continued, whether the last run
    finished, was stopped part-way, or processed other inputs (BASE-016R2).
  - **A non-empty directory without the tool's state** is refused, so the tool never
    writes into an unrelated directory.

  The state database records every file the tool wrote. When a project is rewritten, its
  files that are no longer produced are removed. The resumable-ingest plan implements this
  (BASE-017R1, BASE-021R1).

### BASE-009: Some Markdown renders wrongly: placeholder labels vanish, `{#anchor}` is unsupported, names are not escaped

**Severity:** Low · **Verified:** By inspection · **Where:** `src/cameo_ingest/emit.py:201-202`, `src/cameo_ingest/model.py:108`, `src/cameo_ingest/text.py:21-22`

**Status:** Fixed on 2026-09-29.

These problems affect how the pages look in a Markdown viewer. Chunk text used for
retrieval reads fine.

- **Placeholder labels vanish.** `<unnamed>` and the unnamed-element labels such as
  `<Association>` look like HTML tags, so GitHub and most Markdown viewers hide them.
- **Explicit anchors aren't supported.** The `## Title {#anchor}` syntax is not GitHub
  Markdown. It shows up as literal text, and on GitHub the in-file links don't resolve.
- **Names aren't escaped.** `md_escape` escapes nothing, so a name containing `]`, `|`, `*`
  or `_` can break link labels or change the formatting.

**Remediation:**
- **BASE-009R1 (done):** Use placeholders that aren't HTML, e.g. `(unnamed)` and `(Association)`, in
  both the Markdown and the chunk text.
- **BASE-009R2 (decided 2026-09-29: option (a), open to change later; done):** Write
  `<a id="…"></a>` before each heading, and leave anchors out of chunk text. A raw HTML
  anchor works in GitHub, GitLab, VS Code and Pandoc. The rejected option (b), `{#…}`, only
  works in some renderers, such as Pandoc and kramdown.
- **BASE-009R3 (done):** Escape Markdown-significant characters in link labels and inline names.
  As built, the escaped characters are `\`, `` ` ``, `*`, `[`, `]` and `<`. Underscores are
  left alone: CommonMark doesn't treat an underscore inside a word as emphasis, and model
  names are full of them. Ledger chunk text is unescaped again, so it stays plain.

### BASE-010: Markdown output changes on every run

**Severity:** Low · **Verified:** By inspection · **Where:** `src/cameo_ingest/emit.py:91-103`

**Status:** Superseded by BASE-015, which covers this finding and extends it. The text below
is kept for reference, and the decision in BASE-010R1 is made by BASE-015's remediation.

Every Markdown file's front matter contains `run_id` and `generated`, so each file's
sha256 in the manifest changes on every run even when the source is identical. Chunk
text and chunk IDs don't have this problem. It prevents diffing two runs' output trees
to see what changed.

**Remediation (resolved by BASE-015: run identity is removed from per-file outputs):**
- **BASE-010R1:** The options were:
  - (a) keep the run identity only in `manifest.json` and drop it from per-file front matter;
  - (b) accept the churn and document it.

### BASE-011: No total decompression budget for nested archives

**Severity:** Low · **Verified:** By inspection · **Where:** `src/cameo_ingest/archive.py:22-25`, `:151-152`

**Status:** Fixed on 2026-09-29.

Each archive member is limited to 4 GiB, and compression-ratio checks only start above
64 MiB. Nested members are read fully into memory, up to 4 levels deep, and no limit
applies to the total across the input. A crafted bundle can therefore use much more
memory than any one member limit suggests.

**Remediation:**
- **BASE-011R1 (decided 2026-09-29; done):** Keep a running total of decompressed bytes across the
  whole `discover` call, nested archives included. Stop with `UnsupportedInput` when the
  total passes 10 GB or a member's compression ratio passes 1000:1. As now, the ratio is
  only checked for members over 64 MiB. These limits replace the 4 GiB per-member limit
  and the 400:1 ratio, and they are meant to assume valid input.

  The samples come nowhere near either limit:

  | Measure | Largest in the samples |
  |---|---|
  | Compression ratio | 54:1 (a 2 MB layout stream in NIST_M-SysML) |
  | Single member | 38 MB |
  | Whole input, decompressed | 138 MB (the SAF_Plugin bundle) |
- **BASE-011R2 (done):** Test with the limits lowered and a bundle that exceeds them.

### BASE-012: `.replace(".md", ".png")` rewrites the whole path

**Severity:** Low · **Verified:** By inspection · **Where:** `src/cameo_ingest/pipeline.py:106`

**Status:** Fixed on 2026-09-29.

- **BASE-012R1 (done):** Use `removesuffix(".md") + ".png"`.

### BASE-013: The 64-byte layout check skips almost every diagram layout in TMT

**Severity:** High · **Verified:** Reproduced · **Where:** `src/cameo_ingest/pipeline.py:71-74`

**Status:** Fixed on 2026-09-29.

**Correction:** this finding was first rated Low. The first version said current Cameo
streams begin with a 38-character XML declaration and would pass the check. That was
wrong, and the survey of stream headers made for BASE-019 showed it.

`load_layouts` treats a stream as a diagram layout only if `mdOwnedViews` appears in its
first 64 bytes. TMT's streams begin with `<?xml version='1.0' encoding='UTF-8'
standalone='no'?>`, which is 55 bytes, followed by a newline. The root tag therefore ends
past byte 64, and the stream is skipped as if it were an attachment, without any message.

**Consequences:**
- **Skipped diagrams show nothing.** They get no shapes, no connections, no PNG sketch, no
  vision description, and no "Shown in diagrams" entries on the elements they show.
- **Nothing falls back.** The "Elements shown" list is used only when a diagram has no
  layout, and it is filled from `xmi:idref` values, which Cameo doesn't use in
  `usedObjects`, so it stays empty too.

**Evidence:**
- **Survey of every `BINARY-*` stream in the samples:**
  - TMT: 1,240 of 1,241 layout streams are skipped.
  - TMT-2024x: 1,163 of 1,238 are skipped.
  - Every other sample passes.
- **Fresh TMT ingest:**
  - only 1 of 1,346 diagram pages lists shapes;
  - none list elements shown;
  - only 3 element sections have "Shown in diagrams".

**Remediation:**
- **BASE-013R1 (done):** Find the first start tag, skipping any BOM, XML declaration and
  whitespace, the way `sniff_xmi` does. Don't rely on a fixed byte count.
- **BASE-013R2 (done):** Add a fixture layout stream with a `standalone='no'` declaration, and
  assert that TMT has diagram pages with shapes (covered by BASE-007R3).

**Result:** TMT now has shapes on 1,171 diagram pages, up from 1, and "Shown in diagrams" on
1,853 element sections, up from 3. The other 70 non-empty layouts hold only frames,
paths or decorations. The pinned TMT counts guard this in the slow run.

### BASE-014: `REQ_LINKS["containment"]` can never match

**Severity:** Low · **Verified:** By inspection · **Where:** `src/cameo_ingest/ledger.py:39`, `:106`

**Status:** Fixed on 2026-09-29.

`requirement_row` only considers relationships whose metaclass is `Abstraction`,
`Dependency`, `Realization` or `Usage`. SysML requirement containment is ownership, not

### BASE-015: Timestamps, run IDs and local paths make output unreproducible

**Severity:** Medium · **Verified:** Reproduced · **Reported by:** David Barbour · **Where:** `src/cameo_ingest/emit.py:91-103`, `src/cameo_ingest/cli.py:33-57`, `:113-139`, `src/cameo_ingest/ledger.py:147-150`

**Status:** Fixed on 2026-09-29. On the drone sample, 0 of 43 files now differ between runs, from the same directory or another one (24 of 42 did before).

This finding supersedes BASE-010. The same input run with the same options and tool
version should produce identical output, so that output trees can be diffed, cached and
checked. Today it doesn't:

- **Run identity is in every file.** Every Markdown file's front matter, and
  `index/hierarchy.json`, contain `run_id` and `generated` (the start time).

  change as a result.
- **Local paths are in the text.** The source path is written into Markdown bodies and into

**Evidence:**
- **Two runs of Package_Delivery_Drone** into separate directories: 24 of 42 files differ.
  The differences are front matter `run_id` and `generated`, the `run_id` and `started`

- **The same bytes copied to another directory:** `chunks.jsonl` differs. All 150 chunk IDs
  match, but 15 of those chunks have different text.

**Remediation:**
- **BASE-015R1 (done):** Remove `run_id` and `generated` from per-file front matter and from
  `hierarchy.json`. Keep the tool version, source hash and options, which are deterministic.
- **BASE-015R2 (done):** Separate run-specific data (run ID, times, LLM call counts, failures) from
  a deterministic content manifest. It can go in its own run record or in the state
  database of BASE-021. Document that `generated:*` chunks reproduce only while the LLM
  cache (or that database) is kept. As built, `manifest.json` is deterministic, and the run
  record is a new `run.json` holding the run ID, times, source path, command line and LLM
  call count. The README documents both files and the note about the cache.
- **BASE-015R3 (done):** Keep local paths out of chunk text and Markdown bodies. Name the source by
  file name and content hash, and record paths only in provenance metadata. The exact form

  outputs, and keeps the full path in `run.json`. The BASE-017 plan may change this, for
  example to list every path where the content was seen.
- **BASE-015R4 (done):** Test that two runs on the same input, and one on a copy at another path,

### BASE-016: Different inputs with the same file name share one output directory

**Severity:** Medium · **Verified:** Reproduced · **Reported by:** David Barbour · **Where:** `src/cameo_ingest/cli.py:89-93`, `:116-120`

**Status:** In progress. R1 (the stopgap) is done; R2 waits for the resumable-ingest plan.

A project's output directory is named after the input's file name, plus its path inside

**Remediation:**
- **BASE-016R1 (done):** Add a short-term guard. The project README's front matter already records

- **BASE-016R2:** Name project output by content and let many inputs share one output tree.
  This is tracked by the resumable-ingest plan (BASE-017R1).

### BASE-017: The same content is processed again under every path where it appears

**Severity:** High · **Verified:** Reproduced · **Reported by:** David Barbour · **Where:** `src/cameo_ingest/archive.py:41-56`, `:119-156`, `src/cameo_ingest/emit.py:161-164`, `src/cameo_ingest/provenance.py:61-81`

Identity follows where content was found, not what it is. `SourceInfo.sha256` hashes only
the top-level input. A project inside a bundle is identified by its archive chain, and its
own bytes are never hashed or recorded. Chunk IDs and locators both start from the
top-level hash.

This matters whenever the same `.mdzip` is ingested more than once: standalone and inside
a bundle, from two bundles, or from two paths. Each time it is parsed, rendered and sent
to the LLM again, and it produces a second set of chunks under different IDs, which
become duplicates in a vector store. Only the LLM cache avoids repeating the calls.

The maintainer's intended design is to process each project once per content hash and to
record every path and archive chain where that content was seen, as provenance.

**Evidence:** three of the nine `.mdzip` files inside the SAF release bundles are
byte-identical to standalone samples:

| Inside the bundle | Standalone copy | sha256 |
|---|---|---|
| `SAF_Plugin_2026-09-16.zip!samples/SAF/SAF_FFDS.mdzip` | `samples/SAF_FFDS.mdzip` | `197f8381ad12…` |
| `…!templates/SAF Blank/SAF Blank.mdzip` | `samples/SAF_Blank.mdzip` | `cacc6d6b8e25…` |
| `…!profiles/SAF_Profile.mdzip` | `samples/SAF_Profile.mdzip` | `24fb896309b8…` |

**Remediation:**
- **BASE-017R1:** Write the resumable-ingest plan and add it to `docs/plans/README.md`. It
  should cover:
  - identifying each project by the sha256 of its own bytes;
  - deriving output locations and chunk IDs from that hash;
  - recording every (input path, archive chain) where the content was seen, and carrying
    those into provenance;
  - skipping content that was already processed.

  The plan also covers BASE-016R2 and BASE-021.

### BASE-019: The default LLM call budget silently leaves large models partly enriched

**Severity:** High · **Verified:** Reproduced · **Reported by:** David Barbour · **Where:** `src/cameo_ingest/llm.py:35`, `:45-46`, `:81-85`; `src/cameo_ingest/pipeline.py:23-24`, `:116-117`

**Status:** Fixed on 2026-09-29.

**How the budget behaves:**
- After 500 calls (`CAMEO_INGEST_LLM_MAX_CALLS`, default 500), the run stops calling the
  LLM, logs one warning and carries on.
- Enrichment follows model order, so the first 500 items are described and the rest
  aren't.
- The manifest records only `llm_calls`, not which items were skipped.
- The budget and the timeout can only be changed through environment variables.

**Other limits also cut input without saying so:** package summaries see only the first
12,000 characters of the package text, and diagram descriptions see only the first 150
shapes and 150 connections.

**Evidence:** a full TMT run needs 1,413 calls: 1,241 diagram descriptions, 171 package
summaries and 1 image, counted with BASE-013 fixed. The default budget covers about 35%.
Each rerun gets the next 500 calls from the cache, so finishing TMT takes three runs, and
nothing tells the user that.

**Remediation:**
- **BASE-019R1 (done):** Set no call budget by default, and add `--llm-max-calls N` for anyone who
  wants one.
- **BASE-019R2 (done):** Add CLI flags for the timeout and the retry count, alongside the
  environment variables.
- **BASE-019R3 (done):** Record each item's enrichment outcome (done, from cache, skipped by
  budget, failed) and summarize the counts in the manifest. Log a warning whenever an input
  was cut short to fit the prompt. As built, the counts and the list of items left without
  generated text go into `run.json`, not the manifest. The counts differ between runs
  (fresh answer or cache hit), and BASE-015 requires the manifest to be deterministic.
  Truncated inputs get a debug line each, one warning per project, and a
  `truncated_input` count.
- **BASE-019R4 (done):** Add an option for concurrent LLM calls (`--llm-concurrency N`). At 11 s per
  call, TMT takes about 4 hours one call at a time; the endpoint's rate limits decide the
  useful value. `LLM` already puts a lock around its call counter, but nothing uses threads. As built, requests are queued while rendering and answered after it, in
  a thread pool. Results are attached in submission order, so the output is byte-identical
  to a sequential run (tested). The default stays 1, because a local server that handles
  one request at a time would make queued requests hit their timeout.

### BASE-021: Long runs keep all state in memory and cannot be resumed

**Severity:** High · **Verified:** By inspection · **Reported by:** David Barbour · **Where:** `src/cameo_ingest/cli.py:113-139`, `src/cameo_ingest/pipeline.py:93-185`, `src/cameo_ingest/llm.py:76-94`

**How a run keeps state today:**
- The model index, layouts, annotations and chunks are all held in memory.
- Each project's files are written only when that project finishes.
- `manifest.json`, `chunks.jsonl` and the root ledger are written only at the very end.

**What survives an interruption:** only the LLM response cache, one JSON file per response,
which lets a rerun skip calls that already finished. It isn't a record of progress:

- **Nothing shows how far a run got.**
- **Nothing is marked as finished.**
- **The cache can be corrupted** (BASE-005).

**What a stopped run leaves behind:** a run stopped by Ctrl-C, a crash, a reboot or a lost
SSH session leaves an output directory with no manifest. A restart needs `--force` (see
BASE-008) and repeats all the parsing, layout and rendering work.

**Why this gets worse:**
- **LLM runs are long.** With a real endpoint, TMT alone needs hours of LLM calls
  (BASE-018, BASE-019).
- **Content-addressed processing needs a record.** Processing many inputs by content
  (BASE-017) needs a durable record of which content is already done.

**Remediation:**
- **BASE-021R1:** Covered by the resumable-ingest plan (BASE-017R1). It proposes an SQLite
  database in the output directory that records:
  - inputs, and the content found in them;
  - work status for each project and each item: parse, layout, render, and every LLM
    request;
  - LLM results, which replace the JSON cache and fix BASE-005 by design;
  - run history.

  Each item is committed as soon as it finishes, so a stopped run resumes where it
  stopped. Running again with the same output directory continues the work without
  `--force` (BASE-008R1). Outputs are written so that an interrupted write never leaves a
  half-written file recorded as complete.
